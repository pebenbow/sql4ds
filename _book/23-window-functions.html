11  Window Functions

11.1 Learning Objectives

By the end of this chapter, students will be able to:

  • Explain the difference between window functions and aggregate functions in terms of how output rows are produced.
  • Write a window function using the OVER() clause with PARTITION BY and ORDER BY.
  • Apply ROW_NUMBER(), RANK(), and DENSE_RANK() to assign row rankings within partitions.
  • Compare the behavior of RANK() and DENSE_RANK() when rows share the same value, predicting the output of each.
  • Use LAG() and LEAD() to access values from preceding and following rows within a result set.
  • Compute a running total or cumulative sum using SUM() with an ORDER BY inside OVER().
  • Define a custom window frame using ROWS BETWEEN or RANGE BETWEEN to control which rows each calculation includes.
  • Compute a moving average by combining AVG() with a ROWS BETWEEN N PRECEDING AND CURRENT ROW frame.
  • Apply window functions within a CTE to perform multi-step analyses that reference ranked or lagged values in subsequent steps.

GROUP BY has one significant limitation: it collapses every row in a group down to a single summary row, discarding the individual rows that went into it. Often you want the opposite: keep every row, but attach a calculation to each one that considers the other rows around it, a running total, a rank, a comparison to the row before it. That is exactly what a window function does. This chapter uses the flights table from the nycflights database throughout.

11.2 Window Functions vs. Aggregate Functions

An aggregate function used with GROUP BY turns many rows into few: one output row per group. A window function turns many rows into the same number of rows, each one annotated with a value computed from a “window” of related rows, without collapsing anything. Compare the shape of the two directly. First, a familiar GROUP BY aggregate:

SELECT carrier, ROUND(AVG(dep_delay), 1) AS carrier_avg_delay
FROM flights
WHERE month = 1 AND day = 1
GROUP BY carrier
ORDER BY carrier
LIMIT 5;
5 records
carrier carrier_avg_delay
AA 1.6
B6 6.2
DL -1.8
EV 7.6
F9 -8.0

This collapses every flight down to one row per carrier. Now the same average, computed as a window function instead:

SELECT carrier, flight, dep_delay,
       ROUND(AVG(dep_delay) OVER (PARTITION BY carrier), 1) AS carrier_avg_delay
FROM flights
WHERE month = 1 AND day = 1
ORDER BY carrier, dep_delay DESC NULLS LAST
LIMIT 10;
10 records
carrier flight dep_delay carrier_avg_delay
AA 785 61 1.6
AA 763 33 1.6
AA 1611 16 1.6
AA 753 13 1.6
AA 1837 13 1.6
AA 773 12 1.6
AA 1467 8 1.6
AA 321 7 1.6
AA 1709 7 1.6
AA 745 7 1.6

Every individual flight row survives, and every row belonging to the same carrier shows that carrier’s average delay sitting right alongside its own. Nothing was collapsed; the average was simply attached to each row that contributed to it. That is the defining trait of a window function: it looks across a set of related rows to compute something, but it never reduces the row count.

11.3 The OVER Clause: PARTITION BY and ORDER BY

Every window function is written as function() OVER (...). The OVER clause defines the “window”, the set of rows the function is allowed to look at for each row of output:

function_name(expression) OVER (
    PARTITION BY partition_column
    ORDER BY sort_column
)

PARTITION BY divides the rows into independent groups, just like GROUP BY does, except no rows disappear. Each group is processed separately: a window function never mixes rows from different partitions together. Omitting PARTITION BY entirely treats the whole result set as a single partition, as the COUNT/ROWS BETWEEN examples later in this chapter do.

ORDER BY inside OVER() establishes the order the function should process rows in within each partition. This is completely independent of any ORDER BY at the end of the query, which only controls the order of the final displayed output. Some window functions, like the ranking functions below, are meaningless without an ORDER BY inside OVER(), since rank depends entirely on a defined order.

11.4 Ranking Rows: ROW_NUMBER, RANK, and DENSE_RANK

Three closely related functions assign a rank to each row within its partition, based on the ORDER BY inside OVER(). They only differ in how they handle ties, rows that share the exact same value in the ranking column:

SELECT flight, dep_delay,
       ROW_NUMBER() OVER (ORDER BY dep_delay DESC) AS row_num,
       RANK()       OVER (ORDER BY dep_delay DESC) AS rank_val,
       DENSE_RANK() OVER (ORDER BY dep_delay DESC) AS dense_rank_val
FROM flights
WHERE month = 1 AND day = 1 AND carrier = 'AA' AND dep_delay IS NOT NULL
ORDER BY dep_delay DESC
LIMIT 8;
8 records
flight dep_delay row_num rank_val dense_rank_val
785 61 1 1 1
763 33 2 2 2
1611 16 3 3 3
1837 13 4 4 4
753 13 5 4 4
773 12 6 6 5
1467 8 7 7 6
321 7 8 8 7

Flights 1837 and 753 are tied at a 13-minute delay, and the three functions handle that tie three different ways:

  • ROW_NUMBER() never ties: it assigns 4 and 5, arbitrarily breaking the tie by whatever order the tied rows happen to come out in. Two runs of the same query could assign the tied rows in a different order relative to each other unless the ORDER BY fully disambiguates them.
  • RANK() gives both tied rows the same rank, 4, then skips rank 5 entirely: the next distinct value gets rank 6. This matches how ranks work in a race with a dead heat: two rows share second place, and there is no third place.
  • DENSE_RANK() also gives both tied rows the same rank, 4, but does not skip the next rank: the next distinct value gets rank 5. Dense rank counts the number of distinct values seen so far, with no gaps.

Choosing between them depends on what the rank is meant to represent. Use ROW_NUMBER() when you need a genuinely unique sequence number regardless of ties (for example, to pick exactly one row per group). Use RANK() when ties should be visible as ties, and later ranks should reflect how many rows came before. Use DENSE_RANK() when you want a compact, gap-free scale, such as when the rank itself will be displayed as a category (1st tier, 2nd tier, and so on).

11.5 Looking Ahead and Behind: LAG and LEAD

LAG() retrieves a value from a preceding row within the same partition; LEAD() retrieves a value from a following row. Both take the column to retrieve and, optionally, how many rows back or forward to look (the default is one row).

A natural use is comparing each period to the one before it. This computes each carrier’s average delay per month, then uses LAG() to pull in the previous month’s average for comparison:

WITH monthly_avg AS (
    SELECT carrier, month, ROUND(AVG(dep_delay), 1) AS avg_delay
    FROM flights
    WHERE carrier IN ('AA', 'DL')
    GROUP BY carrier, month
)
SELECT carrier, month, avg_delay,
       LAG(avg_delay) OVER (PARTITION BY carrier ORDER BY month) AS prev_month_avg,
       ROUND(avg_delay - LAG(avg_delay) OVER (PARTITION BY carrier ORDER BY month), 1) AS change
FROM monthly_avg
ORDER BY carrier, month
LIMIT 8;
8 records
carrier month avg_delay prev_month_avg change
AA 1 4.7 NULL NULL
AA 2 6.7 4.7 2.0
AA 3 6.2 6.7 -0.5
AA 4 9.7 6.2 3.5
AA 5 9.4 9.7 -0.3
AA 6 14.7 9.4 5.3
AA 7 9.5 14.7 -5.2
AA 8 5.6 9.5 -3.9

PARTITION BY carrier keeps each carrier’s month-to-month comparison separate from every other carrier’s, and ORDER BY month tells LAG() which row counts as “before.” January has no preceding month within its partition, so prev_month_avg and change are both NULL for the first row of each carrier, exactly as you would expect: there is nothing to look back to. LEAD() works identically but looks forward instead of backward, useful for questions phrased the other way around, such as “how much did next month improve on this one?”

11.6 Running Totals with SUM() OVER

Adding an ORDER BY to an aggregate function’s OVER() clause changes its meaning from “summarize the whole partition” to “summarize everything from the start of the partition up through the current row”, a running total. Applied to a per-month flight count, this produces a cumulative count across the year:

WITH monthly_counts AS (
    SELECT carrier, month, COUNT(*) AS num_flights
    FROM flights
    WHERE carrier = 'DL'
    GROUP BY carrier, month
)
SELECT carrier, month, num_flights,
       SUM(num_flights) OVER (PARTITION BY carrier ORDER BY month) AS running_total
FROM monthly_counts
ORDER BY month
LIMIT 6;
6 records
carrier month num_flights running_total
DL 1 1889 1889
DL 2 1797 3686
DL 3 2133 5819
DL 4 2029 7848
DL 5 1963 9811
DL 6 1952 11763

By month 6, running_total reflects every Delta flight recorded from January through June, while num_flights still shows only that individual month’s count. This same pattern, an aggregate function combined with ORDER BY inside OVER(), works for AVG(), MIN(), MAX(), and any other aggregate: each becomes a “running” version of itself.

11.7 Custom Window Frames: ROWS BETWEEN and RANGE BETWEEN

ORDER BY inside OVER() implicitly defines a frame: the specific slice of the partition a function considers for each row. By default, that frame runs from the start of the partition through the current row, which is exactly what produced the running total above. The frame can be made explicit, and customized, with ROWS BETWEEN:

function_name(expression) OVER (
    ORDER BY sort_column
    ROWS BETWEEN start_bound AND end_bound
)

Common bounds are UNBOUNDED PRECEDING (the start of the partition), N PRECEDING (N rows before the current one), CURRENT ROW, and N FOLLOWING.

ROWS counts physical rows. A related option, RANGE, instead groups rows that tie on the ORDER BY value into the same logical position, treating them as a single peer group rather than counting them individually. The difference only shows up when ties exist:

SELECT flight, dep_delay,
       COUNT(*) OVER (
           ORDER BY dep_delay DESC
           ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS rows_count,
       COUNT(*) OVER (
           ORDER BY dep_delay DESC
           RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS range_count
FROM flights
WHERE month = 1 AND day = 1 AND carrier = 'AA' AND dep_delay IS NOT NULL
ORDER BY dep_delay DESC
LIMIT 8;
8 records
flight dep_delay rows_count range_count
785 61 1 1
763 33 2 2
1611 16 3 3
1837 13 4 5
753 13 5 5
773 12 6 6
1467 8 7 7
321 7 8 10

The two flights tied at a 13-minute delay get rows_count values of 4 and 5, one per physical row, but both get a range_count of 5: RANGE treats every row with the same dep_delay as occupying the same position, so both tied rows see the entire tied group included in their frame, not just themselves. ROWS is the more commonly used and more intuitive option, and is what this book uses by default; reach for RANGE specifically when ties in the ordering column should be treated as a single unit rather than processed one at a time.

11.8 Moving Averages

A moving average (or rolling average) smooths out short-term noise by averaging each point together with a fixed number of the points immediately before it. ROWS BETWEEN N PRECEDING AND CURRENT ROW expresses exactly that frame:

WITH monthly_avg AS (
    SELECT carrier, month, ROUND(AVG(dep_delay), 1) AS avg_delay
    FROM flights
    WHERE carrier = 'DL'
    GROUP BY carrier, month
)
SELECT carrier, month, avg_delay,
       ROUND(AVG(avg_delay) OVER (
           ORDER BY month
           ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
       ), 1) AS moving_avg_3mo
FROM monthly_avg
ORDER BY month
LIMIT 6;
6 records
carrier month avg_delay moving_avg_3mo
DL 1 3.4 3.4
DL 2 6.5 5.0
DL 3 13.5 7.8
DL 4 10.3 10.1
DL 5 10.7 11.5
DL 6 18.0 13.0

moving_avg_3mo for month 3 averages months 1 through 3; for month 4, it averages months 2 through 4, dropping January out of the window as April enters it. Each row’s moving average only ever considers itself and the two months immediately before it, sliding forward one month at a time. Moving averages like this are a standard way to visualize a trend (delay is generally worsening or improving over the year) without the month-to-month noise of the raw values obscuring it.

11.9 Window Functions Inside CTEs

Window function results cannot be filtered directly in the same query’s WHERE clause, because WHERE runs before window functions are evaluated. Wrapping the window function in a CTE, then filtering or sorting in a query that reads from that CTE, is the standard way around this. Building on the LAG() example from earlier in this chapter, here is every carrier’s single best month-over-month improvement in average delay, across the entire dataset:

WITH monthly_avg AS (
    SELECT carrier, month, ROUND(AVG(dep_delay), 1) AS avg_delay
    FROM flights
    GROUP BY carrier, month
),
month_over_month AS (
    SELECT carrier, month, avg_delay,
           ROUND(avg_delay - LAG(avg_delay) OVER (PARTITION BY carrier ORDER BY month), 1) AS change
    FROM monthly_avg
)
SELECT carrier, month, avg_delay, change
FROM month_over_month
WHERE change IS NOT NULL
ORDER BY change ASC
LIMIT 5;
5 records
carrier month avg_delay change
OO 9 -4.9 -68.9
YV 7 22.4 -20.4
FL 8 23.4 -17.8
F9 9 8.3 -13.9
EV 9 11.8 -13.7

Three steps, each in its own named CTE, build on one another: monthly_avg aggregates delay per carrier and month; month_over_month computes each month’s change from the previous one using LAG(); the final query filters out the NULL change values (January has no prior month to compare against) and sorts to find the largest improvements, the most negative change values. Attempting to write WHERE change IS NOT NULL directly against a raw LAG(...) OVER (...) expression in a single ungrouped query would fail, since a WHERE clause cannot reference a window function by definition. Splitting the work into CTEs is what makes filtering and sorting on a window function’s result possible at all, not just more readable.

11.10 Exercises

11.10.1 Reflection

1. In your own words, explain why a window function does not reduce the number of rows in a result set, while GROUP BY does. Use an example that does not appear in this chapter.

2. Two rows are tied for the highest value in a partition. Explain what row number, rank, and dense rank each of those two rows would receive, and what the row immediately after them would receive under RANK() versus DENSE_RANK().

3. Why does WHERE change IS NOT NULL fail if written directly against a query that computes change using LAG(), without a CTE? What does this reveal about the order operations happen in within a SQL query?

11.10.2 Practical

4. Write a query that ranks flights by air_time (longest first) within each dest, using RANK(). Show dest, flight, air_time, and the rank. Limit to dest values 'ORD' and 'ATL'.

5. Write a query that computes each carrier’s total flight count per month, then uses LEAD() to show the following month’s count alongside it, and the change between them. Which carrier had the single largest month-to-month increase in flight count?

6. Using a CTE that computes each carrier’s average arr_delay per month, write a query with a 3-month moving average of that value (current month plus the two before it). Which carrier has the smoothest (least varying) moving average across the year, based on eyeballing the results?

7. Write a query that computes a running total of distance flown, per carrier, ordered by month. By which month does each carrier cross 1,000,000 total miles, if it does at all within the year?

8. A colleague writes ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING for a 3-point moving average and gets different results near the start and end of their data than in the middle. Explain why, and what happens at the very first and very last row of a partition under this frame.
